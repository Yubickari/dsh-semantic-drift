# dsh-semantic-drift · 语义漂移词表

[English](README.md) · **简体中文**

插件在 DSH 中的显示名称为**语义漂移词表**（英文 Semantic Drift Vocabulary）。工具条是唯一的扫描入口，底栏只负责报告状态。

一份可版本化的词表、一个只读扫描器、一个面板：找出同一个业务概念在代码里被写成几种样子，并把"哪种写法才算数"固定下来。

DeepSeek Harness（DSH）Web GUI 插件。对任何仓库可用，不需要构建系统、语言服务器或数据库。

```
侧边栏：语义
┌───────────────────────────────┬──────────────────────────────────────────────┐
│ 概念                          │ device.target_temperature                    │
│  device                   2   │ 规范写法  TargetTemp : °C                    │
│   target_temperature          │ 术语      目标温度, 设定温度                  │
│   device_state                │ ───────────────────────────────────────────  │
│  network                  1   │ 漂移 (2)                                     │
│   NetworkStatus               │   target_temp        高   命名变体            │
│ 未归类                    1   │   src/Device/Panel.cs:42                     │
│                               │   NetworkStatus      高   重复定义            │
│                               │   src/Debug/Enumus/Status.cs:11              │
└───────────────────────────────┴──────────────────────────────────────────────┘
```

## 它解决什么问题

同一个业务概念会在每一层被重新翻译一次——数据库列、DTO、客户端字段、协议枚举、界面文案——然后各自走形。系统里没有任何地方记录"这几个标识符本来说的是同一件事"，于是也没有任何地方能检查它们。

插件只增加一件东西：

```
.dsh/semantics.yaml   ——  概念、规范写法、术语
```

以及三种使用方式：

| | |
|---|---|
| **立词表** | 一份 YAML，记录 `概念 → 规范符号` |
| **找漂移** | 只读扫描，指出代码与词表不一致的位置 |
| **裁决收敛** | 面板与五个 Agent 工具：接受、编辑、或把发现提升为概念 |

## 安装

```bash
# 从 GitHub（当前为私有仓库，需要授权）
dsh plugin --profile desktop add github:Yubickari/dsh-semantic-drift

# 或从本地目录
dsh plugin --profile desktop add link:/path/to/dsh-semantic-drift
```

在 Web GUI 里也可以在「设置 → 插件 → 从源安装」填入同样的 spec。安装后刷新一次页面让浏览器半边加载，侧边栏会出现「语义」。

`lib/` 已随仓库提交，从 git 安装不需要构建。npm 包名 `dsh-semantic-drift` 未被占用，但不是安装的前提。

## 快速开始

1. 在某个工作区打开「语义」面板。
2. 点「创建词表」——写入 `.dsh/semantics.yaml`（含默认排除项，暂无概念）。
3. 点「重新扫描」。**还没有任何概念时也已经有发现**：结构性检测器不需要词表就能指出"同名类型被定义了两遍"，这是冷启动阶段的价值。
4. 用「新建概念」（或 `semantic_upsert` 工具）登记概念，再扫描一次。依赖词表的检测器这才有比较基准。
5. 对打算保留的写法点「接受」：先选**范围**（仅此文件 / 同文件名的所有目录 / 整个符号 / 自定义 glob），弹窗会显示这个范围将静音多少条发现；再写下理由。例外写进词表，下次扫描不再报告，后来的人也能看到当初为什么这么定。概念详情里，每条例外还会显示它当前静音了多少条。

### 跟随工作区

**设置 → 自动跟随工作区** 让面板跟随当前 DSH 工作区：切换会话就切换词表，**但不扫描**——打开面板、切到面板都不会自己开工，所以工作区之间、插件之间切换仍然是廉价的。关闭后固定在你在下拉框里最后选择的工作区，并且这个选择按浏览器记住（不存在项目文件里）。从下拉框主动选一个工作区也会把它固定下来——显式选择优先于跟随。

它的子开关 **自动重新扫描** 只在「自动跟随工作区」开启时可用，且只在跟随把面板切到另一个工作区时触发。手动扫描、以及保存/接受/移除之后的重新扫描不受它影响——那些是你刚刚执行的动作的直接结果。

尚未扫描的工作区会明确说"尚未扫描"（正文上方与底栏各一处），并给出扫描按钮，而不是看起来像一个没有漂移的工作区。

重新进入面板不会把结果丢掉：当前标签页会按工作区记住最近一次扫描，保留时长可配置（默认 10 分钟），所以从别的面板切回来看到的是同一份视图，而不是又被要求扫一次。底栏会标注时间（"扫描于 2 分钟前"）；超过保留时长会亮起一个**实心琥珀徽标**（白字压在加深过的警示色上，明暗主题都清晰可读），词表 mtime 与记录不一致时出现同款徽标。两个徽标本身就是重扫按钮：点一下即重新扫描，悬停有同样的说明。把保留时长设为 0 即关闭这份记忆。

选中的概念标题旁有 **编辑** 与 **删除**。删除会把该条目及它记录的全部「已接受例外」从词表文件里移除；不会改动任何代码，只被它覆盖的发现会回到「未归类」。

### 面板设置

顶部工具条是**纯图标**——重新扫描、新建概念、YAML 原文、设置——样式统一为带边框的按钮；每颗图标悬停时立刻显示说明（自绘提示，不是浏览器那个要等一秒的 `title`），同时带无障碍标签。左侧入口是**语义漂移词表**，与面板标题一致。

重新进入面板会回到上次停留的页面：选中的概念（或"未归类"列表）按工作区记在浏览器里，且只在该概念仍然存在时恢复。搜索词、筛选条件和未保存的编辑器**不会**恢复——那些描述的是当时的动作，而不是位置。

右上角齿轮打开面板自己的设置：

- **自动跟随工作区** —— 见上。
- **自动重新扫描** —— 它的子开关；未开启跟随时禁用，且只在跟随切换工作区时重扫。
- **结果保留时间（分钟）** —— 重新进入面板时复用多久以内的扫描结果；0 表示不复用，每次进入都要手动扫描。

工作区选择器旁有一个模式图标：跟随时是准星，固定时是图钉，悬停显示当前模式与点击后的动作；点一下即切换，与设置里的开关同源。
- **通知自动关闭（秒）** —— `0` 表示不自动关闭。带校验问题的错误提示永不自动关闭，因为那正是需要你阅读并处理的内容。
- **显示低置信度发现** —— 原来放在漂移列表旁的开关。
- **本项目（只读）** —— 当前生效的插件配置（词表路径、提示注入、引用格式、工具最低置信度、扫描预算、检测器）。它们属于插件行，修改入口是 **设置 → 插件 → 语义漂移**，这里只做集中展示，方便一眼回答"这个面板现在到底按什么在跑"。

这里每一项都是**浏览器本地偏好**：不会写入 `.dsh/semantics.yaml`，也不会改变仓库。

### 编辑已接受的例外

例外是一条可维护的记录，不是一枚盖下去的章：概念详情里每一行都有 **编辑** 与 **移除**，超过一条时区块标题旁还有 **清空**。

- **编辑**：范围选择器会带着当前 glob 打开，新范围的静音条数与当前条数并列显示，写宽了可以直接收窄；理由可改，符号不可改——符号是观察到的写法，要换请移除后重新接受。
- **移除**：确认框写明"会有 N 条发现重新出现"，成功后底部提示条提供 **撤销**，按原样加回。
- **清空**：确认框写明条数，撤销会把整组恢复。
- 每一次操作都会在 store 的写队列里**重新读取文件**再改这一条，作用在磁盘上的现状，而不是浏览器手里的旧快照。
- 行上的「当前静音 N 条」来自**扫描时的静音归属**，而不是可见发现列表——被静音的发现按定义就不在那个列表里。显示 0 条意味着这条例外的范围什么都没匹配到，这本身也是值得看见的信息，所以不隐藏。

### 未归类这一页

左侧树里的「未归类」列出的是**没有被任何词表概念认领**的发现。结构性检测器是拿代码和代码比，不需要词表，所以这一页在词表还空着的时候就有内容。只有当某个概念的 `canonical.symbol` 与类型名相同时，对应的发现才会自动归到该概念下；否则由你决定：在弹窗里选一个概念接受它，或者把它登记为新概念（会自动填好建议的 id 与规范符号）。**只加术语不会让这一页变少**，因为术语喂给的是命名变体与术语检测器，不是结构性检测器。

## 词表文件

```yaml
version: 1
meta:
  project: demo
  updated: 2026-10-25
exclude: ["**/node_modules/**", "**/bin/**", "**/obj/**"]
concepts:
  - id: device.target_temperature      # group.name，全局唯一
    terms: ["目标温度", "设定温度"]        # 人怎么称呼它
    kind: quantity                     # entity | quantity | enum | status | reference
    canonical:
      symbol: TargetTemperature        # 代码里必须这么写
      type: double
      unit: "°C"
    note: 设备被要求达到的温度。
    accepted:                          # 已经裁决过的例外，必须带理由
      - symbol: TargetTemp
        path: src/Legacy/**            # glob；省略表示该符号全局接受
        reason: 公开字段保留一个版本
```

`terms` 可以写任何语言：扫描器把它们当纯文本在注释、字符串和资源文件里匹配。本中文文档的示例使用中文术语，[英文文档](README.md)使用英文术语。

写入前一定先校验；校验不通过就**不会写入**，并且给出 YAML 行号或文档路径：

* `id` 唯一且形如 `group.name`；
* `canonical.symbol` 是合法标识符，且全局唯一；
* `terms` 非空，且不能被两个概念共用；
* 每条 `accepted` 必须有 `reason`；
* 每个 glob 必须能解析；
* YAML 语法错误给出行列号，文件保持原样。

保存是规范化的、幂等的：同一份文档存两次得到同样的字节。用原文编辑器手改时保留你自己的格式。

## 检测器

| 检测器 | 置信度 | 信号 |
|---|---|---|
| `duplicate-type` | 高 | 成员名与**取值**都相同：真正的复制，建议合并是站得住的 |
| | 高 | *派生副本*：成员名相同、取值不同、且所有声明共享同一基类——参数化派生，不会再被当作合并候选 |
| | 高 | *同名不同值*：没有共同基类，两侧对这些名字的含义已经不一致 |
| `contract-drift` | 高 | 同名类型的成员不同，或同名成员的**取值**不同 |
| `symbol-variant` | 中 | `canonical.symbol` 的拼写变体（大小写/分隔符、已知错拼、编辑距离 ≤ 2），或*同一契约另一种命名*：与规范类型同基类、同成员、同稳定常量，只是名字不同 |
| `term-unmapped` | 低 | 术语出现在注释或资源里，但规范符号从未在代码中出现 |

成员的**取值**也会参与比较（仅限单行简单字面量）。这补上了一个真实的漏报：两个枚举成员值互换，过去因为只比名字而看起来"完全一致"。

两条二次过滤避免刷屏：变体必须在同一文件里还提到该概念的某个术语，或与规范符号共享首个词元；"契约漂移"的两份声明必须至少共享一个成员，所以两个碰巧都叫 `MainWindow` 的无关类不会被报出来。

刻意排除（比较它们只会产生噪声）：入口类（`Program`/`Startup` 且带 `Main`）、`partial` 声明（单个文件永远看不全成员表）、生成文件（`*.Designer.cs`、`*.g.cs`、`auto-generated` 头）、以及成员少于两个的声明。

语言覆盖：结构性检测支持 C#（`class`/`struct`/`interface`/`record`/`enum`）、TypeScript（`interface`/`type`/`enum`/`class`）、Python（`class`）；其它白名单扩展名仍会为 `term-unmapped` 提供注释/字符串证据。

## Agent 工具

五个工具，任何会话可用，与面板共用同一套校验：

| 工具 | 用途 |
|---|---|
| `semantic_list` | 列出概念；`hasDrift` 会跑一次扫描并只保留有发现的概念 |
| `semantic_get` | 按 id 或符号读一个概念与它的已接受例外；`includeDrift` 追加扫描 |
| `semantic_upsert` | 新建或更新概念（`merge` 保留未提供的字段，`replace` 重建） |
| `drift_scan` | 结构化发现，带检测器名、置信度与引用 |
| `semantic_accept` | 管理已接受例外：`add`（默认）、`update` 改范围或理由、`remove` 移除一条、`clear` 清空一个概念；新增与修改时 `reason` 必填 |

拒绝一律是返回值（`{ ok: false, code, message }`），不抛异常；`drift_scan` 在描述里明确写了只读。开着 `announceToAgent` 时，概念列表与"改字段前先查词表"这条硬约束会作为一节注入提示（最多 200 行，超过 120 个概念时折叠为计数）。

## 配置

| 字段 | 默认 | 含义 |
|---|---|---|
| `vocabularyPath` | `.dsh/semantics.yaml` | 词表路径，相对工作区根 |
| `announceToAgent` | `true` | 是否把词表注入提示 |
| `citationStyle` | `file+symbol` | `path/File.cs::Symbol` 或 `path/File.cs:123` |
| `minConfidence` | `medium` | **工具**报告的最低置信度；面板始终拿到全部并按屏幕开关过滤 |
| `timeoutMs` | `30000` | 单次扫描的时间预算 |
| `maxFindings` | `5000` | 单次扫描上限 |
| `maxFileBytes` | `1048576` | 超过则跳过并计数 |
| `maxFiles` | `50000` | 单次扫描访问文件上限 |
| `detectors` | 全部四项 | 本次扫描启用哪些检测器 |

设置表单由 DSH 依据该 schema 自动渲染，没有手写配置界面。修改设置会重载插件行。

## 保证

* **扫描永不写盘。** 只以读方式打开文件；词表是插件唯一会写的文件。
* **单一写路径。** 面板与工具都经过 store：按文件串行、先校验后写、原子替换。
* **无 daemon、无文件监听、无索引。** 没有后台进程、没有 watcher、没有缓存目录；扫描是你要的时候现算。
* **有界。** 超时与结果上限总会结束一次扫描，结果里写明是哪一个触发的。
* **限定工作区。** 请求只能读写已注册的 DSH 工作区（或 Host 默认目录），其它路径一律拒绝。
* **对"按需现算"的一处有意例外：** 浏览器按工作区把最近一次扫描记在 `sessionStorage` 里一段有界的时间，只用于重新渲染面板、避免重复扫描。它不进入仓库、关闭标签页即失效、Agent 工具永不读取（工具调用一律现扫）。底栏标注结果时间并标记过期，同时比对词表 mtime，词表改过会明确提示而不是静默给出旧结论。
* **可诊断。** `GET /semantic-drift/health` 返回本次激活实际挂载了什么（工具数、路由数、提示注入是否注册）以及生效配置，半挂载的插件会暴露出来而不是静默失效。

真实 1700 文件 C# 仓库上的典型开销：**约 1.2 秒**、读取约 18 MB、不改动任何文件。

## 限制，以及它会在哪里出错

这是词法级工具：它懂标识符、成员名和注释文本，不懂语义。

* **名字不是契约。** 同名类型可能毫无关系；共享成员过滤能去掉大部分，但不是全部。
* **成员表是正则解析的**，不是编译器。非常规声明会被跳过并计数，而不是猜。生成的代码整体跳过。
* **编辑距离很粗。** 只在长度 ≥ 6 的声明类型名上运行，并且还需要共享首词元或同文件出现术语。会有少量"这算同一个概念吗"的中置信度发现——`accepted` 就是为这些准备的。
* **`term-unmapped` 是启发式**（低置信度，默认折叠）：注释里有术语，并不证明代码里该有那个符号。
* **未实现单位检查。** `canonical.unit` 会存储与显示，但 D5（量纲漂移）不在本版本内。
* **跨词元的改名抓不到**：规范写法与观察写法差两次以上编辑时（`SetTemp` vs `TargetTemperature`）不会被当作拼写变体——那是"另一个名字"，需要靠词表里的术语与 `term-unmapped` 记录。
* **面板不能打开文件**，只按配置格式复制引用。也**没有自动修复**：只读扫描之所以能被信任，正因为它从不碰你的代码。
* **暂未附带截图。** 上面的布局是真实面板的示意；首次目视核对后会换成真实数据截图。

## 与 SchemaNode 的关系

设计借用了 [kurapica/schema-node-csharp](https://github.com/kurapica/schema-node-csharp) 的三个判断：语义应当是可版本化的独立实体；有限可枚举的词汇表比无限类型系统更可维护；漂移必须可观测、可裁决，而不是靠人记。**不借实现**——没有 Meta/Property/Relation/Function 建模，没有语义编译，没有代码生成。就是一份 YAML 加一个扫描器。

## 开发

```bash
pnpm install
pnpm typecheck     # 对浏览器半边做 tsc 检查：能抓住"改了名还在调用"的标识符
pnpm test          # 类型检查 + node --test，95 个用例，无测试框架依赖
pnpm build         # esbuild → lib/index.js（host）+ lib/client.js（浏览器）
```

`tsc` 刻意只覆盖浏览器半边：不需要宿主包的类型，而且它正好能抓住"函数在一处被删掉、另一处还在调用"这类 bug——这种 bug 打包器会照单全收，静态渲染也永远走不到那条分支。之后 `test/panel-flow.test.mjs` 里的 4 个流程测试会在 jsdom 里加载**构建产物** `lib/client.js`，用宿主真实响应体桩住 `fetch`，像用户一样驱动面板。

`src/` 是源码，`lib/` 是构建产物并随仓库提交，因此从 git 安装无需构建。浏览器半边按 DSH 的 `window.__ModuleLoader__.load({ id, factory })` 契约封装，React 保持 external；host 半边只导入 `yaml` 与 `@deepseek-ai/schemastery`。

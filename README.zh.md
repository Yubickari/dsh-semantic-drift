# dsh-semantic-drift · 语义漂移词表

[English](README.md) · **简体中文**

一个 DSH 插件：用一份可版本化的词表记录项目的业务概念，只读扫描出代码里把它们写得不一样的地方，并给人和 Agent 一个地方去决定"哪种写法才算数"。

---

## 想法从哪来

它借用了 [kurapica/schema-node-csharp](https://github.com/kurapica/schema-node-csharp) 的三个判断：

1. **语义应当是可版本化的独立实体**，而不是每次从代码里重新推导出来的副产品；
2. **有限可枚举的词汇表**，比无限类型系统更容易保持正确；
3. **漂移必须可观测、可裁决**，而不是指望团队靠记忆维持。

但**不借实现**：没有 Meta/Property/Relation 建模，没有语义编译，没有代码生成。这里只有一份 YAML、一个只读扫描器、一个面板、五个 Agent 工具。

## 它能做什么

- **把每个概念记录一次。** id、人怎么叫它（术语）、种类、规范写法（必要时还有类型与单位）、一句说明——都在一份能像代码一样 review、diff 的 YAML 里。
- **不需要构建系统就能找漂移。** 同一类型被定义两遍、两份定义已经分叉、规范名的拼写变体、注释里出现术语但代码里没有对应符号。不需要编译器、语言服务器或数据库。
- **词表为空时也有发现。** 结构性检测器拿代码和代码比较，所以新项目在登记第一个概念之前就已经有结果。
- **区分"拷贝"和"派生"。** 成员与取值都一样才是拷贝；成员相同、取值不同且共享基类是参数化派生，不能合并；形状相同只是换了名字，是另一份契约。
- **用裁决代替静音。** 接受例外时必须写理由、选最小范围，之后还能改范围、改理由、移除、撤销；每一条例外都显示它当前真正静音了多少条发现。
- **把词表放进 Agent 的上下文。** 五个工具加一节系统提示，让 Agent 知道该叫什么名字，并在不得不偏离时留下记录，而不是自己另起一个名字。

## 它不能做什么

- **它是词法级工具，不懂语义。** 它比较标识符、成员名与注释文本；两个同名但无关的类型仍可能被报出来。
- **它不强制任何事。** 提示里的规则是建议；Agent 可以偏离，唯一的防线是"偏离必须记录"。
- **它不改代码。** 没有自动重命名、自动合并或补丁。扫描之所以能被信任，正因为它从不写你的源码。
- **结构性检测只覆盖三种语言的声明**：C#、TypeScript、Python。其它文件只贡献注释/字符串证据。
- **单位只存不查。** `canonical.unit` 会被展示并做字符串校验，但本版本没有量纲漂移检测器。
- **一个工作区一份词表。** 没有跨仓库视图。

## 安装

DSH 通过 profile 安装插件。加入 bundle 后启用对应行：

```bash
# 从本地目录（当前可用）
dsh plugin --profile desktop add link:/path/to/dsh-semantic-drift

# 仓库公开后，也可以从 GitHub 安装
dsh plugin --profile desktop add github:Yubickari/dsh-semantic-drift
```

Web GUI 里对应「**设置 → 插件 → 从源安装**」。安装后刷新一次页面让浏览器半边加载，侧边栏会出现「**语义漂移词表**」。

`lib/` 已随仓库提交，从 git 安装不需要构建。npm 上的 `dsh-semantic-drift` 这个名字没被占用，但安装并不依赖它。

## 快速开始

1. 在某个工作区打开「语义漂移词表」。
2. 点「创建词表」——写入 `.dsh/semantics.yaml`（含默认排除项，暂无概念）。
3. 点「重新扫描」。**还没有任何概念时就已经有发现**：结构性检测器不需要词表就能指出"同名类型被定义了两遍"，这是冷启动阶段的价值。
4. 用「新建概念」（或 `semantic_upsert` 工具）登记概念，再扫一次。依赖词表的检测器这才有比较基准。
5. 对打算保留的写法点「接受」：先选**范围**（仅此文件 / 同文件名的所有目录 / 整个符号 / 自定义 glob），看清这个范围将静音多少条，再写下**理由**。例外写进词表，下次扫描不再报告，后来的人也能看到当初为什么这么定。

## 面板

- **左侧树**：概念按 id 前缀分组，组内有发现计数、组头有加号，顶部有搜索与快速新建。
- **概念详情**：概念字段、归属它的发现、它的已接受例外——每行都有 **编辑** 与 **移除**，超过一条时区块标题旁还有 **清空**。行上写着"当前静音 N 条"；N 为 0 通常意味着范围什么都没匹配到，这本身也值得看见。
- **工具条**：纯图标的扫描、新建概念、YAML 原文、设置；每颗图标悬停立刻显示说明，也带无障碍标签。工具条是唯一的扫描入口，底栏只负责报告。
- **工作区模式**：工作区下拉框旁的图标——跟随时是准星，固定时是图钉；点一下即切换，与设置里的开关同源。
- **扫描记忆**：重新进入面板时直接展示本标签页已有的结果（默认保留 10 分钟，可配置），不再要求重扫。底栏标注结果时间；超过保留时长亮起实心琥珀徽标，词表文件改过也会出现同款徽标——两个徽标本身就是重扫按钮。
- **记忆页面**：面板会回到上次停留的概念（或"未归类"列表），且只在该概念仍然存在时恢复。搜索词、筛选、未保存的编辑器**刻意不恢复**。
- **YAML 原文**：直接编辑文件；保存前校验，每条问题都带 YAML 行号。
- **未归类**：没有被任何概念认领的发现。词表还空着时这里就有内容，因为结构性检测器不需要词表。可以选一个概念接受它，或把它提升为新概念（id 与规范符号会自动填好）。
- **设置**（齿轮）：自动跟随工作区、工作区切换时是否重扫、扫描结果保留多久、通知停留几秒、是否显示低置信度、以及当前生效配置的只读展示。这些都是**浏览器本地偏好**，不会进入仓库。

## 词表文件

```yaml
version: 1
meta:
  project: demo
  updated: 2026-10-25
exclude: ["**/node_modules/**", "**/bin/**", "**/obj/**"]
concepts:
  - id: device.target_temperature      # group.name，全局唯一
    terms: ["目标温度", "设定温度"]        # 人怎么称呼它
    kind: quantity                     # entity | quantity | enum | status | reference
    canonical:
      symbol: TargetTemperature        # 代码里必须这么写
      type: double
      unit: "°C"
    note: 设备被要求达到的温度。
    accepted:                          # 已经裁决过的例外，必须带理由
      - symbol: TargetTemp
        path: src/Legacy/**            # glob；省略表示该符号全局接受
        reason: 公开字段保留一个版本
```

`terms` 可以写任何语言：扫描器把它们当纯文本在注释、字符串和资源文件里匹配。本中文文档的示例使用中文术语，[英文文档](README.md)使用英文术语。

写入前一定先校验；校验不通过就**不会写入**，并且给出 YAML 行号或文档路径：

* `id` 唯一且形如 `group.name`；
* `canonical.symbol` 是合法标识符，且全局唯一；
* `terms` 非空，且不能被两个概念共用；
* 每条 `accepted` 必须有 `reason`；
* 每个 glob 必须能解析；
* YAML 语法错误给出行列号，文件保持原样。

保存是规范化的、幂等的：同一份文档存两次得到同样的字节。用原文编辑器手改时保留你自己的格式。

## 检测器

| 检测器 | 置信度 | 信号 |
|---|---|---|
| `duplicate-type` | 高 | 成员名与**取值**都相同：真正的复制，建议合并是站得住的 |
| | 高 | *派生副本*：成员名相同、取值不同、且所有声明共享同一基类——参数化派生，不作为合并候选 |
| | 高 | *同名不同值*：没有共同基类，两侧对这些名字的含义已经不一致 |
| `contract-drift` | 高 | 同名类型的成员不同，或同名成员的**取值**不同。若一方是另一方的同名子类（"缺失的成员"其实来自继承），或两方都是私有嵌套助手类，则不报 |
| `symbol-variant` | 中 | `canonical.symbol` 的拼写变体（大小写/分隔符、已知错拼、编辑距离 ≤ 2），或*同一契约另一种命名*：与规范类型同基类、同成员、同稳定常量，只是名字不同 |
| | 中 | *词表拼写不在代码里*：`canonical.symbol` 作为代码 token 全仓不出现，而另一种大小写写法有声明、或作为若干声明的词头 |
| `term-unmapped` | 低 | 术语出现在注释或资源里，但规范符号从未在代码中出现 |

成员的**取值**也会参与比较（仅限单行简单字面量）：两个枚举成员值互换，过去因为只比名字而看起来"完全一致"。一侧是 `struct`、另一侧是 `class` 的拷贝会在消息里点明，因为成员一样，编组与身份语义并不同。

两条二次过滤避免刷屏：变体必须在同一文件里还提到该概念的某个术语，或与规范符号共享首个词元；"契约漂移"的两份声明必须至少共享一个成员，所以两个碰巧都叫 `MainWindow` 的无关类不会被报出来。

刻意排除（比较它们只会产生噪声）：入口类（`Program`/`Startup` 且带 `Main`）、`partial` 声明（单个文件永远看不全成员表）、生成文件（`*.Designer.cs`、`*.g.cs`、`auto-generated` 头）、成员少于两个的声明、同名子类遮蔽基类、以及私有嵌套助手类。

语言覆盖：结构性检测支持 C#（`class`/`struct`/`interface`/`record`/`enum`）、TypeScript（`interface`/`type`/`enum`/`class`）、Python（`class`）；其它白名单扩展名仍会为 `term-unmapped` 提供注释/字符串证据。

## 与 Agent 配合

五个工具，任何会话可用，与面板共用同一套校验：

| 工具 | 用途 |
|---|---|
| `semantic_list` | 列出概念；`hasDrift` 会跑一次扫描并只保留有发现的概念 |
| `semantic_get` | 按 id 或符号读一个概念与它的已接受例外；`includeDrift` 追加扫描 |
| `semantic_upsert` | 新建或更新概念（`merge` 保留未提供的字段，`replace` 重建） |
| `drift_scan` | 结构化发现，带检测器名、置信度与引用 |
| `semantic_accept` | `add`（默认）、`update` 改范围或理由、`remove` 移除一条、`clear` 清空一个概念；新增与修改时 `reason` 必填。定位已有条目用 `previousPath`，`path` 是更新后的新范围 |

开着 `announceToAgent` 时，每个会话都会收到一节提示：它所在工作区的概念，以及配套规则——改名前先查概念、名字与规范符号逐字一致、缺概念先登记、刻意偏离要写理由记录。整节最多 200 行，超过 120 个概念时折叠为计数。

拒绝一律是返回值（`{ ok: false, code, message, issues }`），不抛异常，Agent 可以据此调整。词表文件无法解析时返回 `valid: false` 与前几条问题——读取不会假装项目没有概念，写入在修好之前一律被拒。

它设计的循环是这样的：

1. Agent 接到任务，先 `semantic_get` 查它要动的概念；
2. 词表里没有的概念，先 `semantic_upsert` 登记，再写代码；
3. 改完执行 `drift_scan`，看这次改动有没有引入变体或分叉；
4. 确属刻意的发现，用 `semantic_accept` 带理由、带最小范围接受；
5. 词表的 diff 和其它改动一样走 review。

## 配置

| 字段 | 默认 | 含义 |
|---|---|---|
| `vocabularyPath` | `.dsh/semantics.yaml` | 词表路径，相对工作区根 |
| `announceToAgent` | `true` | 是否把词表注入提示 |
| `citationStyle` | `file+symbol` | `path/File.cs::Symbol` 或 `path/File.cs:123` |
| `minConfidence` | `medium` | **工具**报告的最低置信度；面板始终拿到全部并按屏幕开关过滤 |
| `timeoutMs` | `30000` | 单次扫描的时间预算 |
| `maxFindings` | `5000` | 单次扫描上限 |
| `maxFileBytes` | `1048576` | 超过则跳过并计数 |
| `maxFiles` | `50000` | 单次扫描访问文件上限 |
| `detectors` | 全部四项 | 本次扫描启用哪些检测器 |

设置表单由 DSH 依据该 schema 自动渲染，没有手写配置界面。修改设置会重载插件行。

## 保证

* **扫描永不写盘。** 只以读方式打开文件；词表是插件唯一会写的文件。
* **单一写路径。** 面板与工具都经过 store：按文件串行、先校验后写、原子替换。
* **无 daemon、无文件监听、无索引。** 扫描是你要的时候现算。
* **有界。** 超时与结果上限总会结束一次扫描，结果里写明是哪一个触发的。
* **重复扫描很便宜。** 未改动文件的解析结果按路径、大小与 mtime 复用（1 秒内动过的文件强制重解析），并发的相同扫描共享一次计算；发现本身从不缓存。
* **限定工作区。** 请求只能读写已注册的 DSH 工作区（或 Host 默认目录）；写请求必须指出工作区，缺省会被拒，而不是回落到默认目录。
* **对"按需现算"的一处有意例外。** 浏览器按工作区把最近一次扫描记在 `sessionStorage` 里一段有界的时间，只用于重新渲染面板；它不进入仓库、关闭标签页即失效、Agent 工具永不读取，底栏会标注结果时间。
* **可诊断。** `GET /semantic-drift/health` 返回本次激活实际挂载了什么（工具数、路由数、提示注入是否注册）以及生效配置。

## 限制

这是词法级工具：它懂标识符、成员名和注释文本，不懂语义。

* **名字不是契约。** 同名类型可能毫无关系；共享成员过滤能去掉大部分，但不是全部。
* **成员表是正则解析的**，不是编译器。非常规声明会被跳过并计数，而不是猜；生成的代码整体跳过。
* **编辑距离很粗。** 只在长度 ≥ 6 的声明类型名上运行，还需要共享首词元或同文件出现术语。会有少量"这算同一个概念吗"的中置信度发现——`accepted` 就是为这些准备的。
* **`term-unmapped` 是启发式**（低置信度，默认折叠）：注释里有术语，并不证明代码里该有那个符号。
* **跨词元的改名抓不到**：写法差两次以上编辑时（`SetTemp` vs `TargetTemperature`）不会被当作拼写变体——那是"另一个名字"，靠词表里的术语与 `term-unmapped` 记录注释侧。
* **面板不能打开文件**，只按配置格式复制引用。也**没有自动修复**：只读扫描之所以能被信任，正因为它从不碰你的代码。

## 开发

```bash
pnpm install
pnpm test      # 类型检查 + node --test
pnpm build     # esbuild → lib/index.js（host）+ lib/client.js（浏览器）
```

三层测试，每一层负责前一层看不见的故障：

- `test/*.test.ts`：store、扫描器、检测器、服务与语言字典，使用手工构造的夹具；
- `test/fiber.test.ts`：把**构建产物**的 host 挂到假宿主上，按宿主的方式驱动工具、路由与提示小节；
- `test/*.test.mjs`：渲染组件，并在 jsdom 里驱动**构建产物**的浏览器包，用宿主真实响应体桩住 `fetch`。

`tsc` 刻意只覆盖浏览器半边：不需要宿主包的类型，而且它正好能抓住"函数在一处被删掉、另一处还在调用"这类 bug——打包器会照单全收，静态渲染也永远走不到那条分支。

`src/` 是源码，`lib/` 是构建产物并随仓库提交，因此从 git 安装无需构建。浏览器半边按 DSH 的 `window.__ModuleLoader__.load({ id, factory })` 契约封装，React 保持 external；host 半边只导入 `yaml` 与 `@deepseek-ai/schemastery`。

贡献规则见 [CONTRIBUTING.md](CONTRIBUTING.md)，其中也写明了这个仓库必须遵守的一条：**任何真实项目都不得在任何地方被识别出来**——代码、测试、夹具、文档、提交信息皆然，因为它是针对私有项目开发的。
